## GitLab이란?

GitLab은 Git 저장소를 관리하고 협업을 위한 웹 기반 플랫폼입니다. GitHub와 유사하지만, 오픈소스이며 자체 호스팅이 가능합니다.

### 주요 기능
- **버전 관리**: Git을 통한 코드 버전 관리
- **이슈 트래킹**: 작업 관리 및 버그 추적
- **CI/CD**: 자동화된 빌드, 테스트, 배포
- **코드 리뷰**: Merge Request를 통한 코드 검토
- **위키**: 프로젝트 문서화
- **컨테이너 레지스트리**: Docker 이미지 저장

## 기본 개념

### 1. 저장소 (Repository)
- 프로젝트의 코드가 저장되는 공간
- Git 저장소와 동일한 개념

### 2. 프로젝트 (Project)
- 저장소를 포함한 전체 작업 공간
- 이슈, Merge Request, 위키 등이 포함됨

### 3. 그룹 (Group)
- 여러 프로젝트를 묶어 관리하는 단위
- 조직이나 팀 단위로 사용

### 4. 브랜치 (Branch)
- 코드의 독립적인 버전
- `main` 또는 `master`가 기본 브랜치

### 5. Merge Request (MR)
- 코드 변경사항을 검토하고 병합하는 요청
- GitHub의 Pull Request와 유사

### 6. 커밋 (Commit)
- 코드 변경사항을 저장하는 단위
- 각 커밋은 고유한 해시값을 가짐

## 시작하기

### 1. 계정 생성 및 로그인
1. GitLab 웹사이트 접속 (예: https://gitlab.com)
2. 회원가입 또는 로그인

### 2. SSH 키 설정 (선택사항)
SSH 키를 설정하면 매번 비밀번호를 입력할 필요가 없습니다.

```bash
# SSH 키 생성 (이미 있다면 생략)
ssh-keygen -t ed25519 -C "your_email@example.com"

# 공개키 복사
cat ~/.ssh/id_ed25519.pub

# GitLab에 등록
# 설정(Settings) > SSH Keys에서 공개키 추가
```

### 3. Git 설치 확인
```bash
git --version
```

## 기본 작업 흐름

### 1. 프로젝트 생성

#### 웹에서 생성
1. GitLab 대시보드에서 **"New project"** 클릭
2. **"Create blank project"** 선택
3. 프로젝트 이름, 설명, 가시성 설정
4. **"Create project"** 클릭

#### 로컬에서 기존 프로젝트 연결
```bash
# 프로젝트 디렉토리로 이동
cd your-project

# Git 초기화 (아직 안 했다면)
git init

# GitLab 저장소 추가
git remote add origin https://gitlab.com/username/project-name.git

# 또는 SSH 사용 시
git remote add origin git@gitlab.com:username/project-name.git

# 코드 푸시
git add .
git commit -m "Initial commit"
git push -u origin main
```

### 2. 저장소 클론 (다운로드)
```bash
# HTTPS 사용
git clone https://gitlab.com/username/project-name.git

# SSH 사용
git clone git@gitlab.com:username/project-name.git
```

### 3. 기본 Git 작업

#### 파일 추가 및 커밋
```bash
# 변경사항 확인
git status

# 파일 스테이징
git add filename.txt          # 특정 파일
git add .                     # 모든 변경사항

# 커밋 생성
git commit -m "커밋 메시지"

# 원격 저장소에 푸시
git push origin main
```

#### 브랜치 작업
```bash
# 새 브랜치 생성 및 이동
git checkout -b feature/new-feature

# 또는 (Git 2.23+)
git switch -c feature/new-feature

# 브랜치 목록 확인
git branch

# 브랜치 전환
git checkout main
# 또는
git switch main

# 브랜치 푸시
git push origin feature/new-feature
```

## 주요 기능

### 1. Merge Request (MR) 생성

#### 웹에서 생성
1. 브랜치를 푸시한 후 GitLab에서 **"Create merge request"** 버튼 클릭
2. 제목과 설명 작성
3. 리뷰어(Assignee) 지정
4. **"Create merge request"** 클릭

#### 명령어로 생성
```bash
# 브랜치 푸시 후 GitLab 웹사이트에서 MR 생성
git push origin feature/new-feature
```

### 2. 이슈 (Issue) 관리

#### 이슈 생성
1. 프로젝트 페이지에서 **"Issues"** 탭 클릭
2. **"New issue"** 클릭
3. 제목, 설명, 라벨, 담당자 설정
4. **"Create issue"** 클릭

#### 이슈와 MR 연결
- MR 설명에 `Closes #이슈번호` 또는 `Fixes #이슈번호` 추가
- MR이 병합되면 이슈가 자동으로 닫힘

예시:
```
이 기능을 구현했습니다.

Closes #123
```

### 3. 코드 리뷰
1. MR 페이지에서 변경사항 확인
2. 특정 라인에 댓글 추가
3. 승인(Approval) 또는 변경 요청
4. 모든 리뷰가 완료되면 병합

### 4. CI/CD 파이프라인

#### .gitlab-ci.yml 파일 생성
프로젝트 루트에 `.gitlab-ci.yml` 파일을 생성합니다.

```yaml
# 예시: Node.js 프로젝트
stages:
  - build
  - test
  - deploy

build:
  stage: build
  script:
    - npm install
    - npm run build
  only:
    - main

test:
  stage: test
  script:
    - npm test
  only:
    - main

deploy:
  stage: deploy
  script:
    - echo "Deploying..."
  only:
    - main
```

### 5. 위키 사용
1. 프로젝트 페이지에서 **"Wiki"** 탭 클릭
2. **"Create your first page"** 클릭
3. 마크다운으로 문서 작성

## 실전 예제

### 시나리오: 새 기능 추가하기

#### 1단계: 최신 코드 가져오기
```bash
git checkout main
git pull origin main
```

#### 2단계: 새 브랜치 생성
```bash
git checkout -b feature/user-login
```

#### 3단계: 코드 작성 및 커밋
```bash
# 파일 수정
# ...

# 변경사항 커밋
git add .
git commit -m "Add user login functionality"
```

#### 4단계: 원격 저장소에 푸시
```bash
git push origin feature/user-login
```

#### 5단계: Merge Request 생성
1. GitLab 웹사이트에서 **"Create merge request"** 클릭
2. 제목: "Add user login functionality"
3. 설명 작성
4. 리뷰어 지정
5. **"Create merge request"** 클릭

#### 6단계: 리뷰 및 병합
- 리뷰어가 코드 검토
- 피드백 반영 (필요시)
- 승인 후 병합

#### 7단계: 로컬 정리
```bash
git checkout main
git pull origin main
git branch -d feature/user-login  # 로컬 브랜치 삭제
```

## 유용한 Git 명령어

### 상태 확인
```bash
git status                    # 현재 상태 확인
git log                       # 커밋 히스토리
git log --oneline --graph     # 간단한 히스토리
git diff                      # 변경사항 확인
```

### 되돌리기
```bash
# 마지막 커밋 수정 (메시지만 변경)
git commit --amend

# 파일 변경사항 취소 (아직 커밋 안 함)
git checkout -- filename.txt

# 스테이징 취소
git reset HEAD filename.txt
```

### 원격 저장소 관리
```bash
# 원격 저장소 확인
git remote -v

# 원격 저장소 URL 변경
git remote set-url origin new-url

# 원격 브랜치 확인
git branch -r

# 원격 브랜치 삭제
git push origin --delete branch-name
```

## 모범 사례

### 1. 커밋 메시지
- 명확하고 간결하게 작성
- 무엇을 왜 변경했는지 설명
- 영어 또는 한글로 일관성 있게 작성

예시:
```
✅ 좋은 예: "Add user authentication with JWT tokens"
❌ 나쁜 예: "fix"
```

### 2. 브랜치 네이밍
- `feature/기능명`: 새 기능
- `bugfix/버그명`: 버그 수정
- `hotfix/긴급수정명`: 긴급 수정
- `refactor/리팩토링명`: 코드 리팩토링

### 3. 작은 단위로 커밋
- 논리적으로 관련된 변경사항만 함께 커밋
- 자주 커밋하기

### 4. MR 전에 테스트
- 로컬에서 테스트 실행
- 코드 스타일 확인
- 문서 업데이트

## 문제 해결

### 충돌(Conflict) 해결
```bash
# 최신 코드 가져오기
git pull origin main

# 충돌 발생 시
# 1. 충돌 파일 수정
# 2. 충돌 해결 후
git add .
git commit -m "Resolve merge conflicts"
git push
```

### 실수로 잘못된 브랜치에 커밋
```bash
# 커밋은 했지만 푸시는 안 함
git reset HEAD~1              # 마지막 커밋 취소 (변경사항은 유지)
git checkout -b correct-branch
git add .
git commit -m "Correct commit"
```

### 원격 저장소와 동기화
```bash
# 원격 저장소의 변경사항 가져오기
git fetch origin

# 가져온 후 병합
git merge origin/main

# 또는 한 번에
git pull origin main
```

## 자주 묻는 질문 (FAQ)

### Q: Git과 GitLab의 차이는?
**A:** Git은 버전 관리 시스템이고, GitLab은 Git을 사용하기 위한 웹 플랫폼입니다.

### Q: Merge Request는 언제 사용하나요?
**A:** 코드를 검토받고 병합하기 전에 사용합니다. 팀 협업 시 필수입니다.

### Q: 커밋을 실수로 푸시했어요. 어떻게 하나요?
**A:** 
- 아직 MR이 없다면: `git reset` 후 강제 푸시 (주의!)
- 이미 MR이 있다면: 새 커밋으로 수정하는 것이 안전합니다.

### Q: 여러 사람이 같은 파일을 수정하면?
**A:** Git이 자동으로 병합을 시도하지만, 충돌이 발생할 수 있습니다. 충돌은 수동으로 해결해야 합니다.
